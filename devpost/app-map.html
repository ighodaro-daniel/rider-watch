Rider Watch — App Map

A take-home guide to the finished proof of concept: what one action does, where its code lives, and where to start when you want to change something.

What the app is

Rider Watch is one small Node.js/Express web app that runs on your computer. The owner signs in, adds recipients to reach, and watches two riders move on a dark Leaflet map — either simulated from the dashboard's ▶ Demo control or shared from a rider's real phone over a temporary HTTPS link. When a rider reaches the recipient it is carrying, the delivery is marked arrived, the dashboard chimes, and the owner ticks it received. Recipients, monitoring choices and received ticks live in data/db.json; live positions stay in server memory. The plan and reasoning are in devpost/prd.md and devpost/spec.md.

One action: press ▶ Demo

You have already used this one. Here is the whole path from your click to the moving dot, in the order it happens.

  1. Click ▶ Demo in the RIDERS panel. → public/dashboard.html, button #demo-riders. The browser runs the click handler in public/js/dashboard.js.
  2. Ask the server to start or stop. → POST /api/dev/simulation with { on: true }. src/routes.js checks the owner session first, then calls demo.start() or demo.stop().
  3. The server walks the riders. → src/demo.js, tick() once a second. src/route-plan.js moves each rider one eightieth of the way along its current leg, and the new position is saved and broadcast.
  4. The dashboard receives it and moves the dot. → src/ws.js broadcast() sends a position message; connectLive() and moveRider() in public/js/dashboard.js ease the dot across the second.
  5. Result on screen. → The dot glides and leaves a trail. If that rider's parcel is within 50 m, src/arrival.js marks it arrived, the alert message reaches the dashboard, and you hear the chime.

Stop 2 — the guarded door: src/routes.js

Search /api/dev/simulation (line 114). requireOwner means a signed-out browser is redirected instead of starting the demo — dev mode is still the owner's dashboard, not a public switch. The reply is just { running: true } or { running: false }.

Stop 3 — the movement: src/demo.js

Search function tick (line 35). Each tick calls plan.advance(route, cursor) from src/route-plan.js to get the next point, store.setPosition(...) to remember it, broadcast({ type: 'position', ... }) to push it out, and checkArrivals(position, rider.id) to see whether this rider reached one of its own parcels. On the browser side, moveRider() (line 517 of public/js/dashboard.js) sets the target and easeRiders() (line 497) glides toward it.

A practice to reuse

Reproduce it outside the browserWhen something looks wrong on screen, send the same request from a terminal before changing any interface code. It separates a UI problem from a server problem in one step.

This happened here. Signing in at http://localhost:3000 while the phone-test server was running bounced straight back to the login page, which looked like a rejected passphrase. Sending the form with curl showed the real shape of it:

Show the request that explained it 
curl -i -X POST http://localhost:3000/login \
  -d 'username=owner&password=rider-watch'

# HTTP/1.1 302 Found
# Location: /dashboard.html
# Set-Cookie: connect.sid=...; Path=/; HttpOnly; Secure; SameSite=Lax

The server accepted the passphrase; it was the cookie that was wrong. In share mode the cookie had been marked HTTPS-only, so a plain-http browser would not send it back and /dashboard.html redirected to the login page. The fix was narrow — in server.js, mark the cookie Secure only when the request really is HTTPS (req.secure) — and the check that proves it stayed the same two curl commands: local login then dashboard 200, tunnel login then dashboard 200. Next time a screen misbehaves, try the request without the screen first; it usually says which half is broken.

Running it again

npm install       # once
npm start         # http://localhost:3000
npm run share     # phone-test mode: adds a temporary HTTPS link (needs cloudflared)
npm run simulate  # optional: the standalone simulator instead of ▶ Demo

Sign in with the owner ID and passphrase from config.json. Tick a rider, then press ▶ Demo to watch the route play. Data lives in data/db.json and is git-ignored, so restarting keeps your route.
